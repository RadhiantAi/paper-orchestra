# Research review audit, 15 November 2026

The fork now includes an offline adversarial benchmark, numerical consistency
checks, evidence decisions, controlled section revisions, deeper discovery,
optional read-only connected sources, rights-aware PMC passages and publication
status checks. See RESEARCH_REVIEW.md for configuration and operating limits.

## Findings fixed during review

- Later citation-chasing failures discarded earlier successful reference fetches.
  Successful results are now retained with a partial/failure report.
- Changing a selected collection or connector configuration could leave the same
  resume settings. The run settings now include hashes of those input files.
- Aggregate constraint failures could coexist with a clean top-level numerical
  status. They now mark the review as needing attention.
- A revision could leave earlier evidence and numerical reports appearing current.
  Revisions now mark those derived reports stale.
- A numerical audit with no recognised items could appear to have passed. It now
  reports `not_checked`.
- Publication metadata identity conflicts could be treated as ordinary records.
  They now carry a distinct status and are excluded by the automatic writer.
- Streamable HTTP responses could wait for a persistent SSE stream to close.
  The transport now stops after the matching completed JSON-RPC response.
- A complex LaTeX table could lose leading counts during Word conversion while
  retaining percentages. Word export now checks recognised count/percentage pairs
  before promoting the file. Chat-assisted Markdown can be exported directly,
  avoiding that intermediate conversion. Render review is still required.

## Validation

Earlier review/discovery stage: 108 passed, 1 skipped. The skipped test requires a running Docker
daemon. Critical Ruff checks and dependency consistency checks passed. The tests
block external network connections; UI tests allow only their local event-loop
socket. UI interaction tests save evidence decisions, preview and accept revisions,
and confirm that another section's approval is preserved.

Three synthetic benchmark cases detect seeded numerical, invented-claim,
missing-evidence and retracted-source defects; their corrected fixtures pass.
This is a deterministic regression benchmark, not a model-quality leaderboard.

## Remaining limits

No paid model calls were made for this validation. Production provider runtime,
real Zotero/Brave credentials, MCP OAuth lifecycle and arbitrary server schemas
remain outside this test. The MCP client requires host-managed tokens and a
selected tool returning the documented record schema. It does not implement
stdio, OAuth login/refresh or paginated tool inventories.

Crossref update metadata is incomplete; unknown status is not evidence of absence
of retraction. PMC access and reuse depend on available rights metadata and service
availability. Lexical evidence matching does not establish entailment. Numerical
checks cover recognised pairs and explicitly mapped facts, not all possible
scientific errors. Local reviewer names are audit labels, not authenticated
institutional signatures. Private manuscript trials and their data are excluded
from this repository.

## Manuscript project workflow, subsequent validation

The post-trial implementation adds a private source index, tracked-edit comparison,
conditional author queries, discussion coverage, approved aggregate results,
figure provenance, deterministic masking and checked Word/PDF/ZIP packs. Schema 1
host exchange supports evidence supplied by any interactive assistant. See
`PROJECT_WORKFLOW.md` and the synthetic examples for operation and exact limits.

The final local suite passed 130 tests; one Docker TeX integration test was skipped.
The three existing adversarial benchmark cases passed. Critical Ruff checks,
additional F-series checks on new modules, dependency consistency and whitespace
checks passed. New regression fixtures contain synthetic material only.

Additional findings fixed during this implementation:

- Repeated PDF running headers could interrupt a paragraph spanning pages and
  produce false Word/PDF text mismatches. Marginal repeated headers and page
  numbers are excluded from the comparison.
- A neighbouring highlighted run or comment could satisfy a question check.
  The requested text must itself be yellow and covered by a comment range.
- An image could be repackaged into a PDF with different file bytes. Known
  unmasked originals are checked using decoded pixels as well as file hashes.
  Altered or lossy copies still require visual privacy review.
- Conditional confirmation could rely on a similar label. Exact-match conditions
  require the complete anchored passage; source-evidence conditions remain a
  separate reviewer judgement.
- Source, conversion, result, caption or output changes could leave approval
  records appearing current. Checks now bind to the relevant content and files.
- Resolved generated questions could remain highlighted on rebuild. Their own
  annotations are removed while preserving unrelated and overlapping reviews.
- Case-colliding filenames, symlinks and prior failed-build markers could weaken
  pack integrity. They now fail the applicable build/release checks.

A private replay indexed earlier manuscripts, a thesis, a legacy DOC file and
presentation images, and recovered tracked edits/comments. It tested real Word
conversion and rendering, confirmed unchanged manuscript text and title-page
bytes, checked masking receipts, and verified a new local ZIP from its packaged
bytes. All twelve rendered manuscript pages were visually inspected. The earlier
issued pack and mail draft were left unchanged. Clinical confirmations and an
image-only source needing OCR remained open. No model API calls were made.

This replay checks a software workflow. It does not reapprove clinical claims,
reproduce arbitrary external statistical calculations or prove that every earlier
editorial idea has been addressed. Empty topic mappings and missing statistical
asset receipts remain explicitly unchecked. Review packs may retain these pending
items; submission packs cannot pass with them unresolved.
